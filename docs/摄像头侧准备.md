# 摄像头侧准备（TL-IPC682XD-A4 / TP-Link 通用）

程序能不能收到运动事件、网页能不能播放，八成取决于这一步。**先做完这一步再去点「测试连接」**。

## 1. 找到摄像头地址

路由器后台的 DHCP 客户端列表里找，或者用 TP-Link 的手机 APP 看设备 IP。建议在路由器上给它绑定固定 IP，
否则重启后 IP 变了程序就连不上。

## 2. 打开摄像头网页

浏览器访问 `http://摄像头IP`，用摄像头自己的管理员账号登录（**不是** TP-Link 云账号）。

## 3. 开启 ONVIF（默认是关的）

`设置 → 网络设置 → 网络服务 → ONVIF`

- 勾选 **开启 Open Network Video Interface**
- **Onvif 端口**：固件 1.6 及以上一般是 `80`，更早的固件是 `2020`。记下来，填到程序里
- **时间校验 / Time Verification**：**建议关掉**。开着的时候，摄像头和电脑时间差超过几分钟，
  ONVIF 鉴权就会一直失败（报 401）。关不掉的话就让摄像头走 NTP 同步，并保证电脑时间准确

改完点「保存」。

## 4. 确认 Digest 算法

同一页的「Digest 认证算法」选 `MD5` 或 `MD5/SHA256`。程序只支持 MD5 和 SHA-256 两种，
如果选了纯 `SHA256` 而程序报鉴权失败，就改成 `MD5/SHA256`。

## 5. 打开移动侦测并允许上报（关键！）

`设置 → 事件 / 报警 → 移动侦测`

- **启用**
- 画出侦测区域（全屏就行）
- **灵敏度**：从中间值开始试，太低不触发，太高会一直录
- **布防时间**：改成全天，否则只有布防时段才推事件
- **联动 / 上报**：勾选「报警上报」「上传到中心」这类选项。
  有的固件叫「通知管理 / 报警推送」，不勾这个，ONVIF 事件通道里什么都收不到

> 这一项如果不生效，程序的「事件自检」页会一条事件都收不到。这时有两个选择：
> ① 回摄像头网页继续找上报开关（不同固件位置不一样）；
> ② 改用画面比对方案（见 AGENTS.md 风险清单第 1 条）。

## 6. 确认编码是 H.264

`设置 → 视频 / 音视频 → 主码流`

- **编码格式**：选 `H.264`。选 H.265 的话浏览器基本放不了（Safari 和装了 HEVC 扩展的 Edge 例外）
- 分辨率 1080p 足够；4K 会让单片体积翻几倍，但也更清楚，自己权衡
- **码率**：2~4 Mbps 比较均衡。太高 WebDAV 上传慢、手机看卡
- **I 帧间隔 / GOP**：如果能看到，设成帧率的 1~2 倍（如 25fps → 50），段边界更干净

子码流一般是 720p / H.264，如果想省带宽可以把程序的「录像码流」设成子码流。

## 7. RTSP 地址

程序会自动通过 ONVIF 拿。拿不到时的默认格式：

```
主码流  rtsp://用户名:密码@摄像头IP:554/stream1
子码流  rtsp://用户名:密码@摄像头IP:554/stream2
```

可以先在 VLC 里「打开网络串流」贴一下，能播说明 RTSP 通。

## 8. 防火墙

第一次启动程序时 Windows 会弹「是否允许访问网络」，**选「专用网络」并点允许**。
如果当时点了取消，手机就打不开网页：控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙，
找到 `OnvifWebDav.App.exe` 勾上「专用」。

## 9. 用程序自检确认

按这个顺序点，每一步都有中文结果：

| 步骤 | 位置 | 期望结果 |
|---|---|---|
| 测试 ONVIF 连接 | 摄像头页 | 显示型号/固件，时钟偏差 < 30 秒 |
| 获取 RTSP 地址 | 摄像头页 | 输入框里出现 `rtsp://IP:554/stream1` |
| 探测编码 | 摄像头页 | `h264`。如果是 `hevc` 请看上面第 6 步 |
| 抓一帧快照 | 摄像头页 | **本机型不支持**：ONVIF 声明 `SnapshotUri=false`，按钮会自动变灰，属正常现象，不影响录像 |
| **事件自检** | 事件自检页 | 人在镜头前走动，**至少 2 次「运动开始」** |

事件自检页右上角能选「推送 / 轮询」。默认「自动」：设备支持 `WSSubscriptionPolicySupport`
就走推送（设备 POST 到 `http://本机IP:网页端口/onvif/notify`），显示「实际使用：BasicNotification（推送）」。

**推送模式要注意**：摄像头必须能访问到这台电脑的网页端口。Windows 防火墙要放行，
且这台电脑的 IP 不能在摄像头重启后变（路由器上绑定固定 IP）。收不到会自动退回轮询，不会漏录。

命令行验证（更直接，能看到原始 XML）：

```
dotnet run --project tools/OnvifWebDav.Probe -- notify-test --host 摄像头IP --user admin --pass 密码 --seconds 120
```

事件自检是硬门槛：**2 分钟一条都没有，后面做的全是白搭**。
